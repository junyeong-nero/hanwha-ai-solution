# 모임 의사결정 통합 검증 — #36

이슈 #36은 상위 Epic이다. 이 변경은 이미 병합된 장소 비교(#34), 일정 조율(#33), 공유 의견(#32), 안 읽음(#12), 홈 관계 그래프(#29)의 연결 구간을 보강한다. 열린 #35·#30·#15·#31 구현과 Epic 전체 완료는 별도 작업이다.

## 변경 사항

- 약속 카드에서 의견 수집으로, 확정 결과에서 채팅방으로 바로 이동한다.
- 로컬 데모의 의견 수집 방·응답·확정 결과는 공유 URL 없이 일반 데모 주소로 재접속해도 복원한다. 일정 조율의 기존 저장 정보보다 의견 수집 상태를 우선한다.
- 공유 의견 화면은 채팅방을 열지 않았어도 최종 확정을 구독한다. 재연결 시 놓친 확정을 조회하고 작성 중 의견을 보존한 채 입력을 잠근다. 화면 닫기·로그아웃 시 구독을 해제한다.
- 늦은 추천 응답이 의견 수집·확정을 되돌리지 않으며, 확정된 카드와 채팅 배너의 장소·시간을 함께 갱신한다.
- 데모 추천 버튼을 연달아 눌러도 하나의 후보 카드만 생성한다.

## 자동 검증

`npm ci && npm test` — Node.js 24 이상. 통합 회귀 6개를 포함해 총 199개 통과.

`tests/decision-flow.test.mjs`는 일반 URL 복원, 확정 복원, 이전 일정과의 충돌, 지연 응답, 배너 갱신, 공유 화면의 확정·재연결·구독 해제, 데모 추천 중복 방지를 검사한다. 기존 PGlite 테스트는 실제 PostgreSQL에서 방장 확정 RPC와 참여 권한·마감·기존 확정 경로 차단을 검사한다.

## 모바일 재현 절차

2026-09-07, Playwright WebKit 26.6, 375×812에서 아래 흐름을 확인했다.

1. `src/?demo=1` → 매칭 → 새 모임 만들기. 이름·태그를 입력하고 연결된 친구 한 명을 초대한다.
2. 채팅방 → AI 추천 약속 잡기 → 카드의 `장소·시간 의견 모으기` → 의견 수집 시작.
3. 두 번째 장소·가능 시간 두 칸·기타 의견을 선택한다. 제출 전 요약 → 수정 → 제출 후 응답 완료를 확인한다.
4. 공유 링크 없이 일반 `src/?demo=1` 주소로 다시 접속한다. 채팅 목록의 모임 → 의견 화면에서 선택과 의견이 복원되는지 확인한다.
5. 방장 비교 화면에서 후보별 득표와 1/2명 응답을 확인하고, 장소·미래 시간을 골라 최종 확정한다.
6. 일반 데모 주소로 다시 접속해 채팅 카드·상단 배너·방장 확정 메시지의 장소·시간을 확인한다.
7. 확정 결과 → `채팅방에서 약속 보기` → 만남 완료. 두 명의 완료와 사진첩 개방·연결 상태를 확인하고 홈으로 이동한다.

이 시나리오에서 JavaScript 오류와 문서 가로 넘침은 없었다. 초대한 친구는 이미 연결된 사람이므로 이 시나리오로 신규 연결 수 증가까지 검증했다고 보지는 않는다.

## 검증 범위

- 실제 iPhone Safari 기기 검증, 운영 Supabase의 다중 사용자 Realtime, 외부 AI·카카오 장애 주입은 이번 로컬 검증에 포함하지 않았다. Realtime 처리는 모의 채널·재연결 테스트, 권한과 확정은 PGlite RPC 테스트로 확인했다.
- Supabase 스키마·Edge Function 변경이나 운영 배포는 없다.
- 데모의 의견·약속 복원과 별개로 일반 대화·만남 완료·평가 상태는 기존 세션 동작을 유지한다.

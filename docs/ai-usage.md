# OpenAI API 활용

사용자 소유의 OpenAI API 키와 `gpt-5.4-mini`를 사용해 **AI 모임 매칭**과 **AI 장소 추천**을 구현한다. 구현 기준은 [features.md](features.md)이며, 운영 활성화에는 사용자 키 등록과 두 Edge Function 배포가 필요하다([배포 절차](deployment.md#6-openai-확인-발표-전날당일--모임약속-추천)).

## 공통 연결 방식

- 브라우저 → Supabase Edge Function → OpenAI Responses API 순서로 호출한다.
- 사용자 API 키는 Supabase Secret의 `OPENAI_API_KEY`에 등록하고, 모델은 `gpt-5.4-mini`로 설정한다. 실제 키는 소스·문서·브라우저에 넣지 않는다.
- 응답은 구조화된 JSON으로 받고 서버에서 후보 ID와 필수 필드를 검증한다. 입력에는 필요한 정보만 포함하고, 실명·사번은 전달하지 않는다.
- 호출 시간 제한과 오류 시 대체 경로를 두고, 모델·지연 시간·성공 여부를 기록한다. 로컬 데모 모드는 외부 API 없이 유지한다.

## 1. AI 모임 매칭

- **입력:** 저장된 관심사·취미·희망 인원·관계 방향과 후보 모임의 제목·태그·인원·아는 사람 비율 등.
- **처리:** `recommend-meetings`에서 선호 지역·열림 상태·정원을 먼저 확인하고 기존 규칙 점수를 계산한다. 미참가 모임 상위 20개에 대해 GPT가 관심사의 의미적 연관성과 선호를 종합해 후보의 최종 순위를 정한다. 예를 들어 ‘러닝’과 ‘한강 조깅’의 연관성을 반영한다.
- **출력:** 모임 ID, 순위, 개인화된 추천 이유, 주의점. 서버는 후보 밖 ID와 중복을 검증하고 이미 참가한 모임은 뒤로 배치한다.
- **안정성:** 실패하면 기존 `rankByRules()` 결과를 사용한다. 서버 인스턴스 내 최대 100개·60초 캐시를 쓰며 사용자·프로필·후보 변경 시 재계산한다. 브라우저도 60초 후 탭 진입 시 새 목록을 조회한다.

## 2. AI 장소 추천

- **입력:** 모임 지역·관심사, 호출자가 참가한 이후의 최근 대화(발신자를 ‘참가자 N’으로 치환), 실제 장소 검색 결과.
- **처리:** `suggest-meeting-plan`의 약속 생성 모델을 OpenRouter에서 GPT로 전환한다. 카카오 로컬 검색으로 장소 후보를 확보하고, GPT가 대화에 맞는 장소·시간·활동·주변 맛집 및 카페를 제안한다.
- **출력:** 약속 제안과 후보 장소 목록. 장소 ID·주소·좌표·상세 링크는 검색 결과로 채우고, 검색에 없는 장소는 제거한다. 최종 장소 선택·약속 확정은 기존 사용자 흐름을 따른다.
- **안정성:** GPT 호출 실패 시 검색 후보 기반 기본 카드를 제공한다. 검색 실패 시 상태와 대체 검색어를 안내한다. 운영 경로는 OpenRouter 웹 검색을 호출하지 않으며 카카오 검색을 사용한다. 검색 결과가 없으면 GPT를 호출하지 않는다.

## 확인 방법

샘플 프로필로 기존 순위와 AI 순위를 비교하고, 지역·정원 조건 준수, 후보 밖 ID 차단, 실제 장소 검증, API 오류 시 대체 동작을 확인한다. 두 기능 모두 호출 비용과 응답 시간을 측정한다.

모델의 Responses API·구조화된 출력 지원: [OpenAI 공식 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini).

- OpenAI 요청은 본문 수신까지 20초, 출력 최대 4,000토큰으로 제한하고 실패 시 재시도 없이 기본 결과를 제공한다. API에는 `store: false`를 지정한다.
- 자동 검증: `npm test`의 `openai-recommendations.test.mjs`에서 API 모의 응답으로 순위·캐시·오류·장소 검증을 확인한다. 실제 계정의 호출 성공·비용·지연은 키 등록 후 배포 환경에서 별도로 확인한다.

## 프로젝트 주제

**05. Great Challenger · 자유주제**

신입사원이 조직 안에서 새로운 동료를 발견하고 실제 만남으로 이어지도록 돕는 AI 활용 사내 네트워킹 서비스입니다.

## 해결할 문제와 대상

대상은 한화 그룹사 신입사원을 중심으로, 다른 부서·직무·계열사의 동료와 교류하고 싶은 구성원입니다. 회사에 많은 사람이 있어도 개인이 자연스럽게 만나는 범위는 같은 팀, 부서, 입사 동기처럼 이미 접점이 있는 사람에게 집중되기 쉽습니다. 누가 나와 관심사가 비슷한지, 어디서 함께 만날 수 있는지 알기 어렵고 처음 말을 거는 부담도 있습니다.

해결하려는 문제는 사람의 부족이 아니라 서로를 발견할 기회와 자발적으로 만나고 싶은 이유의 부족입니다. MoonLight Hanwha는 관심사와 생활권으로 모임을 발견하고, 닉네임 대화로 시작해 함께 약속을 정한 뒤 실제 만남으로 연결하는 모바일 웹앱입니다. 만남을 강제로 배정하지 않고 구성원이 참가와 공개 시점을 선택하도록 설계했습니다.

## 현재 상황과 불편

기존 관계 형성은 같은 조직에서 반복적으로 마주치는 사람이나 교육·행사에서 우연히 만난 사람에 의존합니다. 단체 채팅이나 일회성 교류 행사는 대화의 시작점은 제공하지만, 나에게 맞는 모임을 찾고 실제 약속까지 정하는 과정을 충분히 지원하지 못합니다.

불편은 세 단계에서 나타납니다. 첫째, 동료의 관심사와 활동 지역을 알기 어려워 공통점을 찾기 어렵습니다. 둘째, 실명과 직장 관계가 먼저 드러나는 환경에서 처음 말을 거는 데 부담을 느낄 수 있습니다. 셋째, 대화가 시작되어도 장소 검색과 시간 조율이 여러 메시지에 흩어져 약속 확정까지 이어지지 않을 수 있습니다.

외부 근거로 잡플래닛의 직장인 470명 조사에서는 58.6%가 회사의 일부 사람들과만 친하게 지낸다고 답했습니다. 또한 일터우정과 이직의도의 관계를 다룬 2025년 연구는 조직의 사회적 관계와 개인-조직 적합성의 중요성을 보여줍니다. 이는 문제 설정의 참고 자료이며, 한화 구성원 대상 자체 설문이나 우리 서비스의 효과 검증 결과는 아닙니다. [잡플래닛 조사](https://www.jobplanet.co.kr/contents/news-7193), [KCI 연구](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003292988)

## 활용 자료·데이터

- **문제 정의 자료:** 잡플래닛 직장인 인간관계 조사와 「중소기업 근로자의 피드백 환경 및 일터우정과 이직의도의 관계에서 개인-조직 적합성의 매개효과」(유승완·박난주·이찬, 2025). 관계 형성의 필요성을 설명하는 외부 자료로 사용했습니다.
- **시연 데이터:** 직접 구성한 샘플 프로필, 계열사 목록, 모임, 채팅, 약속 후보입니다. 제출 영상은 로컬 데모이며 다른 참여자의 답장·투표·만남 완료는 시뮬레이션입니다. 사진첩도 예시 화면입니다.
- **사용자 입력:** 닉네임, 계열사, 선호 지역, 나이, 관심사·취미, 희망 인원, 관계 방향 등입니다. 저장된 설정을 모임 추천의 입력으로 사용합니다.
- **대화 데이터:** 백엔드 약속 추천은 해당 방의 최근 대화 최대 30개를 메시지당 최대 300자로 제한하고 발신자를 참가자 번호로 바꿔 LLM에 전달합니다. 프로필의 실명·사번은 별도로 전달하지 않지만, 대화 본문에 직접 쓴 개인정보를 자동으로 제거하지는 않습니다.
- **장소 데이터:** 백엔드에서 카카오 로컬 검색 등으로 확보한 장소명·주소·좌표·링크를 후보 검증과 지도에 사용합니다. 검색 실패나 미확인 상태는 화면에서 구분합니다.
- **검증 자료:** 저장소의 자동 테스트, PGlite PostgreSQL RPC 실행 검증, 모바일 데모 회귀 기록입니다. 실제 사내 운영 성과 데이터는 아직 없습니다.

## 사용한 AI·자동화 도구

**Claude Code, OpenAI Codex, OpenRouter, Supabase, 카카오 로컬 검색·지도, GitHub Pages, Node.js 테스트, Playwright, Python, FFmpeg.**

Claude Code와 Codex는 요구사항 정리, UI·백엔드 구현, 코드 검토, 오류 수정, 테스트와 제출 자료 정리에 활용했습니다. 사람이 정한 기능 명세와 저장소 규칙을 바탕으로 결과를 검토하고 실제 동작을 확인했습니다.

서비스의 생성형 AI는 OpenRouter를 통한 LLM 호출입니다. 자유로운 채팅 맥락에서 장소·시간·활동을 정리하는 약속 추천에 사용합니다. 모임 순위는 관심사·관계 성향·인원 등 구조화된 입력을 처리하는 규칙 기반 추천 엔진으로 구현했습니다. 같은 입력의 순위가 재현되고 대기 시간과 호출 비용이 줄도록 역할을 구분했습니다.

Supabase는 인증·데이터 저장·권한 검사·실시간 반영을, 카카오는 실제 장소 검색과 지도 표시를 담당합니다. Playwright로 시연 화면을 녹화하고 Python과 FFmpeg로 자막·배경음을 합성했습니다. 제출 영상은 TTS 없는 자막판입니다.

## AI·자동화 흐름

1. **입력:** 사용자가 프로필과 원하는 만남 방식을 저장합니다. 관심사·지역·관계 방향 등을 추천 조건으로 사용합니다.
2. **모임 추천:** 규칙 엔진이 관심사, 관계 방향, 희망 인원, 계열사·성별 선호, 잔여석을 반영해 모임을 정렬합니다. 사용자가 직접 참가할 모임을 선택합니다.
3. **익명 대화:** 참가자는 닉네임으로 대화합니다. 첫 인사 추천 칩과 모임별 채팅으로 대화를 시작할 수 있습니다.
4. **AI 처리:** 사용자가 약속 추천을 요청하면 서버가 참여 권한을 확인하고 제한·가명 처리한 대화를 LLM에 전달합니다. LLM이 장소·시간·활동·주변 식사를 제안합니다.
5. **자동 검증:** 장소 검색 결과와 후보를 대조하고 주소·좌표 등을 보완합니다. 모델 응답 오류나 지연에는 재시도·기본 제안으로 대응하고, 검색 상태를 안내합니다.
6. **사람의 확인:** 참여자가 지도와 목록에서 후보를 비교합니다. 기존 카드에서는 전원 투표로 확정하거나, 의견 수집을 시작해 각자의 장소·가능 시간·기타 의견을 모은 뒤 방장이 최종 확정합니다. 의견 수집 중에는 기존 자동 확정 경로를 막습니다.
7. **출력과 후속 행동:** 확정된 장소·시간을 채팅 카드와 배너에 반영합니다. 실제 만남 후 각자가 만남 완료를 누르면 서로 완료한 상대와 실명이 공개되고, 홈에 새로운 연결이 반영됩니다.

로컬 데모는 이 흐름을 샘플 데이터로 재현합니다. 실제 LLM 호출·다중 사용자 데이터 공유는 백엔드 연결 모드에서 제공합니다.

## 만든 과정

1. 신입사원의 관계 형성 문제를 정리하고 외부 조사·연구를 참고해 ‘만날 이유를 발견한다’는 방향을 정했습니다.
2. 홈·매칭·채팅·프로필의 4탭과 프로필 설정 → 참가 → 대화 → 약속 → 만남 → 연결의 핵심 흐름을 기능 명세로 고정했습니다.
3. HTML·CSS·일반 JavaScript로 모바일 프로토타입을 구현했습니다. 계열사를 행성으로, 만남 이후의 연결을 행성 점등과 궤도로 표현했습니다. iOS의 안전 영역과 입력 확대, 터치 영역, 동작 감소 설정을 고려했습니다.
4. Supabase Auth·PostgreSQL·RLS·Realtime과 Edge Functions를 연결했습니다. 브라우저의 공개 키와 서버의 비밀 키를 분리하고 방 참여·확정·실명 공개 권한을 서버에서 검사하도록 구성했습니다.
5. 추천을 반복 검토하며 구조화된 모임 순위는 규칙 엔진으로 바꾸고, 자유 대화 해석이 필요한 약속 제안에 LLM을 사용했습니다. 장소 검증과 오류 안내를 추가했습니다.
6. 실제 사용 흐름을 점검해 첫 프로필 설정 안내, 모임 상세, 첫 인사, 안 읽음 배지, 후보 비교, 시간 조율, 공유 의견 제출·방장 확정을 보강했습니다. 재접속 상태 복원과 늦은 응답의 덮어쓰기 문제를 회귀 테스트로 확인했습니다.
7. PR 통합 과정에서 충돌, 중복 알림 구독, DB 마이그레이션 번호 중복, 탈퇴 RPC와 투표 취소 반영 문제를 수정했습니다. 통합 코드의 자동 테스트 205개가 통과했고 새 RPC는 PGlite에서 실행 검증했습니다.
8. 모바일 데모를 녹화해 1분 54초 자막 영상으로 제작하고, 14장 HTML 발표 자료와 본 보고서로 제출 내용을 정리했습니다.

제작은 사람이 문제와 사용자 경험을 판단하고 AI 코딩 도구가 구현·수정안을 생성하며 테스트로 확인하는 방식으로 진행했습니다. 팀원별 실제 이름과 역할 배분은 제출자 확인 후 기입합니다.

## 완성한 결과

**MoonLight Hanwha 모바일 웹앱 프로토타입과 제출용 영상·발표 자료·보고서를 완성했습니다.**

- 홈: 연결된 동료와 계열사를 우주 형태로 표현하고 만남 이후 관계 변화를 보여줍니다.
- 매칭: 저장한 프로필에 따른 정렬, 모임 상세 확인, 참가·생성, 아는 사람 비율을 제공합니다.
- 채팅: 익명 대화, 첫 인사, 안 읽음 표시, AI 약속 추천, 후보 지도, 전원 투표와 공유 의견 기반 방장 확정을 제공합니다.
- 프로필: 추천 조건 설정·저장과 처음 사용하는 사람을 위한 안내를 제공합니다.
- 만남 이후: 상호 만남 완료에 따른 실명 공개, 평가, 예시 사진첩, 홈 연결 반영을 시연합니다.

핵심 데모 흐름은 실행 가능한 수준입니다. 백엔드 코드는 구현했지만 운영 Supabase의 다중 사용자 통합 검증과 실제 iPhone 기기 검증까지 완료했다고 주장하지 않습니다. 추가된 모임 나가기·투표 취소·멤버 관심사의 서버 반영에는 `0015` 마이그레이션 적용 확인이 필요합니다.

제출 영상은 114.402초, 1920×1080, 30fps, H.264/AAC 형식이며 전체 디코딩 오류가 없음을 확인했습니다. 생성형 음성 없이 화면 자막 22개와 직접 합성한 배경음을 사용합니다. 발표 HTML은 14장으로 구성하고 이미지·폰트를 포함해 별도 설치 없이 열 수 있도록 만들었습니다.

## 효과와 활용 가치

**확인한 변화:** 모임 탐색, 채팅, 후보 비교, 시간·장소 의견, 최종 약속을 하나의 흐름으로 연결했습니다. 대화에서 결정 사항을 다시 찾아야 하는 부담을 줄이고 확정 결과를 같은 화면에서 확인할 수 있습니다. 모임 추천은 구조화된 규칙으로 재현 가능하게 만들었고, 발표용 데모는 외부 연결 없이도 핵심 흐름을 보여줍니다.

**기대효과:** 신입사원의 첫 대화 부담을 낮추고, 공통 관심사를 통해 다른 조직 구성원과 자발적인 교류를 시작하도록 도울 수 있습니다. 반복적인 만남은 소속감과 정보 공유, 장기적인 부서·계열사 간 협업의 기반이 될 가능성이 있습니다.

시간 절감률, 이직률 감소, 조직 소속감 향상 수치는 아직 측정하지 않았습니다. 파일럿에서는 모임 참가율, 약속 확정률, 실제 만남 완료율, 새로 연결된 동료·계열사 수, 재참여율, 만남 만족도를 관찰하고 사전·사후 설문과 인터뷰로 이유를 확인할 계획입니다. 비교 기준과 목표치는 모집 규모와 운영 기간을 정할 때 합의합니다.

## 막힌 점과 한계

- LLM은 지연·형식 오류·미확인 장소를 만들 수 있어 타임아웃, 재시도, 기본 제안과 검색 검증을 함께 구현해야 했습니다.
- 채팅·의견·약속 상태가 실시간 이벤트와 새로고침에서 엇갈릴 수 있어 서버 권한 검사와 클라이언트 복원·구독 정리가 필요했습니다.
- 프로토타입의 데모 계정·샘플 데이터는 사내 SSO와 실제 직원 운영을 대신하지 않습니다. 실제 서비스에서는 동의·탈퇴·삭제·보관 정책과 운영 절차가 필요합니다.
- 실명·사번을 별도 프롬프트에 넣지 않더라도 사용자가 대화 본문에 적은 개인정보는 남을 수 있습니다. 외부 LLM에 보낼 정보의 범위와 처리 방침을 파일럿 전에 확정해야 합니다.
- 사진첩은 예시이며 실제 사진 업로드·보관과 신고·차단, 푸시 알림 등은 후속 범위입니다. 평가가 추천 모델을 자동 학습시키는 기능도 아직 구현하지 않았습니다.
- 자동 테스트와 모바일 시연은 확인했지만 운영 환경의 다중 사용자·장애·성능 검증 및 실제 조직 효과 검증은 별도입니다.

## 배운 점

AI를 많이 호출하는 것보다 작업 성격에 맞게 사용하는 것이 중요했습니다. 정형적인 순위 계산은 규칙으로 처리하고 비정형 대화의 정리는 LLM에 맡기자, 추천 이유와 실패 지점을 설명하기 쉬워졌습니다.

AI가 작성한 코드도 사용자 흐름과 권한 관점에서 검토해야 했습니다. 개별 기능이 동작해도 다른 PR과 합치거나 재접속·지연 응답이 발생하면 문제가 생길 수 있었습니다. 기능 명세, 저장소 규칙, 실제 PostgreSQL 실행 검증, 회귀 테스트를 함께 사용하는 방식이 유용했습니다.

서비스의 가치는 기능 수보다 행동의 연결에서 드러났습니다. 공통점 발견 → 부담 없는 대화 → 합의한 약속 → 실제 만남 → 관계의 가시화가 자연스럽게 이어져야 사용자가 다음 행동을 선택할 수 있습니다.

## 다음 적용 계획

1. **운영 준비:** 전용 Supabase 환경에 마이그레이션·Edge Functions를 반영하고 실제 기기와 여러 계정으로 의견 수집·확정·탈퇴·실명 공개를 검증합니다. API 한도·비용·지연·실패 대응도 점검합니다.
2. **자발적 파일럿:** 신입사원 또는 희망자를 대상으로 작은 범위에서 시작합니다. 수집 목적·외부 AI 전송·탈퇴·삭제·보관 조건을 안내하고 운영 담당자를 정합니다.
3. **효과 측정:** 참가 → 확정 → 완료의 전환, 신규 연결, 재참여, 만족도와 소속감 설문을 함께 확인합니다. 낮은 전환 구간은 인터뷰로 원인을 파악합니다.
4. **개선과 확장:** 파일럿 결과에 따라 추천 가중치와 사용 안내를 조정하고, 사내 SSO·사진 저장·신고·차단·알림을 검토합니다. 충분한 평가 데이터가 쌓인 후 추천 학습의 필요성과 방법을 결정합니다.
